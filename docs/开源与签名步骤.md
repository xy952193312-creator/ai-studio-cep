# 开源 + 免费签名：要做的六步

目标：用 SignPath Foundation 免费拿到 Windows 信任的代码签名。
**前提是把源码公开到 GitHub 公开仓库** —— 这是人家免费给你签名的交换条件。

> ⚠️ 公开是**不可逆**的。就算之后删库，爬库和 fork 可能已经留了副本。
> 第 0 步先确认一遍再往下走。

---

## 第 0 步：已经替你做好的清理（做之前先核对）

| 处理 | 内容 |
|---|---|
| 删除 | `docs/DESIGN.md` 里「原插件逆向结论」整节（含对方插件形态、ID、技术栈、色值） |
| 删除 | README / DESIGN 里「UI 风格参考某商业插件」的声明 |
| 改写 | `theme.css`、`index.html`、`app.js`、`api.js` 注释里的「对应原插件…」→ 中性表述 |
| 排除 | `tools/`（含 Inno Setup 第三方软件 + **硬编码了你真实 API 域名的测试脚本**） |
| 排除 | `logs/`（真实用户名和绝对路径）、`screenshots/`、`_img2img_test/` 图片、`dist/` |

代码本身检查过：`extension/` 下**没有硬编码密钥、没有硬编码第三方 API 端点**，
`CSInterface.js` 是自己重写的垫片，不是 Adobe 官方库的拷贝。

**还请你自己再看一眼**：

```bash
git status --porcelain --ignored | grep '^!!'   # 看看被排除的都有谁
git diff --cached --name-only                    # 看看要提交的都有谁
```

---

## 第 1 步：配置 git 身份并提交

这一步没替你做 —— 身份是你的 GitHub 账号，不该由我猜。

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"

git add -A
git commit -m "AI Studio for Photoshop v1.2.14"
```

文件已经 `git add` 过了，直接 commit 就行。

---

## 第 2 步：建 GitHub 公开仓库并推送

1. github.com → New repository
2. **Public**（必须，SignPath 要能审查代码和 CI）
3. 仓库名建议 `ai-studio-cep`
4. **不要**勾 "Add a README / .gitignore / LICENSE" —— 本地都有了，勾了会冲突

```bash
git remote add origin https://github.com/<你的用户名>/ai-studio-cep.git
git branch -M main
git push -u origin main
```

---

## 第 3 步：申请 SignPath Foundation

到 <https://signpath.org> → Apply for Free Code Signing，提交：

| 字段 | 填什么 |
|---|---|
| 项目名 | AI Studio for Photoshop |
| 仓库地址 | `https://github.com/<用户名>/ai-studio-cep` |
| 许可证 | MIT（仓库根目录的 LICENSE） |
| 项目描述 | Photoshop CEP 面板，用自定义 API 做文生图 / 图生图，含历史记录与本地资料库 |
| 构建方式 | GitHub Actions（`.github/workflows/release.yml`） |

**它审核什么**：OSI 许可证、公开仓库、活跃维护、**不含专有代码**、
CI 构建可审查、团队开 MFA、每次签名有人审批。

审核通常 1–2 周，通过会邮件给你：Organization ID、API Token。

---

## 第 4 步：在 GitHub 里配好 secrets

Settings → Secrets and variables → Actions：

Secrets（保密）：

| Name | Value |
|---|---|
| `SIGNPATH_API_TOKEN` | SignPath 邮件里的 API Token |

Variables（不保密）：

| Name | Value |
|---|---|
| `SIGNPATH_ORGANIZATION_ID` | SignPath 给的 Organization ID |

SignPath 侧还要做两件事（在它的控制台里）：

1. 建 Project，slug 填 `ai-studio-cep`（要和 workflow 里的 `project-slug` 一致）
2. 建 Artifact Configuration，slug `setup-exe`，**根元素必须是 zip**
   （GitHub 的 artifact 本来就是 zip 包）
3. 建 Signing Policy，slug `release-signing`，绑定 Foundation 证书
4. **启用 GitHub Actions Trusted Build System** 并关联到这个项目 ——
   漏掉这步，签名请求会被拒

> 没配这些也能发版：workflow 里 SignPath 那几步带 `if:` 判断，
> 变量为空就跳过，照样发布未签名的包。不会红。

---

## 第 5 步：打个 tag 触发构建 + 签名

```bash
git tag v1.2.14
git push --tags
```

Actions 里会依次跑：装 Inno Setup → 编译 → 上传产物 → **提交签名** →
**校验签名状态必须是 Valid** → 生成安装说明 → 发 Release。

校验那一步是故意加的：签名"跑完了"和"真签上了"是两回事。
token 失效或策略配错时，流水线照样全绿，发出去的却还是没签名的包。

---

## 第 6 步：验证

从 Release 下载 exe：

- 右键 → 属性 → 有「数字签名」选项卡 = 签上了
- 发布者显示 **SignPath Foundation**（不是你的名字，这是免费方案的代价）
- 双击时的拦截会明显减轻，但**不会立刻彻底消失** ——
  OV/EV 现在都要靠发布者信誉积累，连签几个版本、下载量上来之后才会没

---

## 如果中途不想开源了

回退到不签名的方案：`dist\安装说明.txt` 已经生成好了，
把 exe 和这个说明一起发给对方即可（含 SHA256 校验和解除锁定的步骤）。
整个过程零成本，代价是对方会看到一次拦截提示。
